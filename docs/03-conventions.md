# Правила и конвенции

Правило, которое можно проверить машиной, проверяется машиной: `.oxlintrc.json` для кода в
`<script>`, `test/architecture/conventions.spec.ts` для разметки, стилей, дерева файлов,
зависимостей и документации. Этот файл объясняет, зачем правила такие.

## Именование компонентов

| Путь                                 | Тег               |
| ------------------------------------ | ----------------- |
| `app/components/ui/Button.vue`       | `<UiButton>`      |
| `app/components/ui/Card/Article.vue` | `<UiCardArticle>` |
| `app/components/app/NavDrawer.vue`   | `<AppNavDrawer>`  |
| `app/components/page/Layout.vue`     | `<PageLayout>`    |

`index.vue` и `Component.vue` запрещены: Nuxt съедает `index` и не съедает `Component`, и в
проекте появляются имена вида UiButtonPrimary рядом с WidgetsAppBurgerMenuComponent.

Список папок с префиксами в `nuxt.config.ts` — белый список: файл в папке, которой там нет,
Nuxt не зарегистрирует. Тест не даст забыть добавить новую папку.

## Компонент знает только про себя

`ui/` не импортирует сторы и не читает предметные поля. Как только компонент понадобился
второй странице из другого раздела — он переезжает в `ui/`.

## Маршруты и адреса

- список — `раздел/index.vue`, детальная — `раздел/[slug].vue`;
- адрес списка всегда канонический: `?page=1`, `?q=` и мусор уводятся редиректом 301,
  номер за пределами списка — редиректом 302 на последнюю страницу;
- пагинация — ссылки, у каждой страницы списка свой canonical;
- результаты поиска закрыты от индексации (`noindex, follow`).

## Стили

- цвет, отступ, радиус, слой — только переменной из `app/assets/styles/`;
- брейкпоинты — миксинами `media-down` (`width < X`) / `media-up` (`width >= X`) из `_tools.scss`,
  `@media` с шириной мимо них роняет тест; числа — в `shared/utils/breakpoints.ts`, оттуда же
  их берёт JS (Swiper);
- размер, который на мобильном меньше, — `fluid($min, $max)`, а не лесенка из `media-down`;
- `@include hover` вместо `:hover`, `@include motion` для переходов;
- утилиты каркаса: `content-wrapper`, `grid-12` + `col-N`, `grid-cards`, `card-surface`,
  `radius-*`, `caption-*`, `text-*`, `visually-hidden`;
- префикс `_` у локальных классов (`._Button`);
- контраст текста — не ниже 4.5:1, фокус — `outline`, а не `box-shadow`.

## Данные и состояние

- всё, что влияет на содержимое экрана, — в URL (`usePagedList`);
- локальное для компонента — `ref`;
- общее UI-состояние — стор Pinia (`app/stores/`), бизнес-данные — из API, не из стора;
- сервер отвечает формой `{ data, meta: { pagination } }`, клиент не догадывается.

## Зависимости

Один пакет на одну задачу. Новая зависимость вытесняет старую для той же задачи. У каждой
зависимости есть место потребления — import, модуль в конфиге или команда в `scripts`; пакеты,
которые работают иначе (компилятор SCSS, типы Node), перечислены в тесте с причиной.
Платформенные бинарники oxlint/oxfmt вручную не пинятся.

## Проверки и что каждая не видит

| Проверка         | Видит                                                | Не видит                    |
| ---------------- | ---------------------------------------------------- | --------------------------- |
| `pnpm lint`      | код в `<script>`, циклы импортов                     | `<template>` и `<style>`    |
| `pnpm typecheck` | типы и props в разметке, тесты, конфиги              | поведение                   |
| `pnpm test`      | чистые функции, правила дерева, компоненты по одному | страницу целиком в браузере |
| `pnpm build`     | собираемость                                         | что страница работает       |
| `pnpm test:e2e`  | гидрацию, CSP, консоль, клики, фокус, редиректы      | визуал                      |
