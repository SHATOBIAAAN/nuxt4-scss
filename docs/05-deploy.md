# Выкатка

## Артефакт

```bash
pnpm build                  # → .output/ (Node-сервер Nitro, самодостаточный)
NUXT_PUBLIC_SITE_URL=https://example.com node .output/server/index.mjs
```

`.output` не содержит `node_modules`: копия на хостинг — это `rsync` одной папки. Сборка от
окружения не зависит, поэтому один и тот же `.output` едет на стенд и на прод.

## Переменные процесса

| Переменная      | Значение                                     |
| --------------- | -------------------------------------------- |
| `PORT`, `HOST`  | порт и адрес привязки (по умолчанию 3000)    |
| `NUXT_PUBLIC_*` | адрес и название сайта, окружение, адрес API |
| `NUXT_CSP_*`    | режим CSP и адрес для отчётов                |

Полный список с пояснениями — в `.env.example`.

## Ловушка привязки, из-за которой «сайт не открывается»

`nuxt dev` слушает `[::1]`, `node .output/server/index.mjs` — `[::]`. Если IPv4-порт занят
другим процессом, запрос к `localhost` уходит не туда. Для проверки — свободный порт и явный
адрес: `PORT=4411 node .output/server/index.mjs`, затем `curl -i http://127.0.0.1:4411/`.
Смотри и на заголовки: нет `content-security-policy` — стучался не в этот процесс.

## Откат

Держать последний проверенный `.output` рядом (`releases/<дата>/`) и перекидывать симлинк
`current`. Откат — смена симлинка и рестарт, а не пересборка в момент аварии.

## Что проверить после выкатки

1. `curl -I /` — 200 и заголовок `Content-Security-Policy`;
2. `/robots.txt` и `/sitemap.xml` — боевой домен, в карте есть статьи;
3. `/несуществующая` — 404 статусом;
4. `/api/posts?page=0` — 400, а не 500.
