# nuxt4-scss

Каркас Nuxt 4 без предметной логики: разложена архитектура, стоят токены, работает BFF-слой,
показан паттерн страницы, а правила проекта проверяет машина — линтер, архитектурные тесты и
e2e в браузере.

## Запуск

```bash
corepack enable
pnpm install
pnpm dev
```

Прод-сборка поднимается с адресом сайта (без него сервер не стартует):

```bash
pnpm build
NUXT_PUBLIC_SITE_URL=https://example.com node .output/server/index.mjs
```

## Что менять первым делом

1. `app/config/nav.ts` — навигация и контакты;
2. `nuxt.config.ts` → `site` — название и описание (или переменные из `.env.example`);
3. `app/assets/styles/colors.scss` — палитра бренда;
4. `app/assets/styles/layout.scss`, `app/assets/styles/_tools.scss` и `shared/utils/breakpoints.ts` —
   сетка, отступы, миксины и числа брейкпоинтов;
5. `shared/schemas/post.ts` + `server/mock/posts.ts` — своя сущность вместо поста.

## Проверки

| Команда          | Что ловит                                                            |
| ---------------- | -------------------------------------------------------------------- |
| `pnpm fmt:check` | формат                                                               |
| `pnpm lint`      | ошибки в `<script>`, циклы импортов, `process.env` в `app/`          |
| `pnpm typecheck` | типы и props в шаблонах, тесты и конфиги                             |
| `pnpm test`      | чистые функции, правила дерева файлов и зависимостей, компоненты     |
| `pnpm build`     | собираемость                                                         |
| `pnpm test:e2e`  | браузер: консоль, гидрация, CSP, ссылки, поиск, пагинация, меню, 404 |

`pnpm check` — первые четыре разом. Pre-commit гоняет `oxlint --fix` и `oxfmt` по staged-файлам,
CI — всё, включая e2e.

## Чего в шаблоне нет намеренно

Корзина, профиль, auth, каталог с фильтрами, CMS-интеграция, аналитика и капча — предметная
логика конкретного проекта. `@nuxt/scripts` подключён модулем и ждёт первого стороннего скрипта —
тогда же настраивается consent.
